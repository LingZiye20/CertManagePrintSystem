# 证书管理与打印系统

面向 Windows 单机使用的证书数据管理与打印桌面应用（模块化单体，PySide6 + SQLite）。

## 环境要求

- Python 3.11.4（64 位，Windows）
- 依赖版本固定在 `requirements.txt` / `requirements-dev.txt`

## 安装

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

## 启动

```powershell
.\.venv\Scripts\python.exe -m app.main
```

## 测试

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

## 目录职责

| 目录 | 用途 |
|---|---|
| `app/` | 应用代码，入口为 `app/main.py` |
| `resources/` | 只读资源（图标、内置模板），打包后兼容 `_MEIPASS` |
| `data/` | SQLite 数据库 `certificates.db` |
| `photos/` | 系统管理的学生照片 |
| `logs/` | 运行日志 `app.log`（5 MB × 3 轮转） |
| `config/` | 独立存放的运行期配置文件（预留） |

所有运行期数据保存在程序所在目录，不使用 `%LOCALAPPDATA%`。源码运行时以项目根为基准，打包后以可执行文件所在目录为基准，`_MEIPASS` 仅用于只读资源。

## 写入权限与移动说明

- 程序目录必须可写；若安装到 `Program Files` 等受保护目录，启动时会明确提示并终止写入。
- 移动或复制整个程序目录即可同时迁移数据库与照片；请先退出程序，避免复制正在写入的数据库文件。
- 不要只复制可执行文件而遗漏 `data/` 与 `photos/`，否则会丢失业务数据与照片。

## 数据库

- 数据库文件位于程序目录下 `data/certificates.db`，启动时自动创建。
- Schema 版本记录在 `schema_meta` 表的 `schema_version` 键，当前为 v1。
- 初始化是幂等的：每次启动都会补建缺失的表与索引、补齐缺失的默认编号规则与流水记录，
  但不会覆盖已有业务数据、用户修改过的规则或已推进的流水值。
- 数据库版本高于程序支持范围、或数据库缺少版本记录却已含业务表时，程序会明确报错并拒绝启动，
  不会删库重建。
- 日期字段统一保存为 `YYYY-MM-DD` 文本；时间戳统一保存为 UTC ISO-8601 文本
  （如 `2026-10-22T10:00:00.000Z`）。
- 三类编号规则（毕结业、学位、其他）的四段固定文本初始为空，默认启用，流水均从 1 开始；
  `sequence_width = 4` 是**项目初始默认配置**，不是提示词包规定的固定值，后续允许用户修改。
- 内置默认模板的 JSON 结构已在阶段 8 确定，资源位于 `resources/templates/`；
  启动流程仍不会自动写入内置模板，首次初始化与系统重置的播种将在后续阶段接入。

## Repository 层

- 代码位于 `app/repositories/`，覆盖 `certificate_records`、`numbering_rules`、`number_sequences`、
  `app_settings`、`certificate_templates`、`operation_logs`、`print_records`、`import_batches`
  共 8 张业务表；`schema_meta` 仍由数据库初始化模块管理。
- 查询结果统一返回 `dict`（单条不存在时为 `None`）；更新/删除返回 `bool` 表示是否命中记录；
  数据库约束错误（如 `sqlite3.IntegrityError`）原样抛出，不转换为空结果。
- 写方法可选传入调用方事务连接：Repository 不提交、不回滚、不关闭该连接，且连接必须处于
  显式事务中，否则抛 `ValueError`。
- Repository 不包含编号生成、Excel 解析、照片文件操作、模板渲染、打印调用或业务编排。
- `certificate_records` 支持可选 `filters`：`student_no` 精确匹配，`name/class_name/major_name/faculty_name`
  包含匹配；筛选值与计数使用同一条件，`LIKE` 中的 `\`、`%`、`_` 会被转义。

## Service 层

- 代码位于 `app/services/`，当前提供 `StudentService`、`NumberingService` 与 `PhotoService`，
  供 UI 调用，不直接拼接 SQL。
- 学号必填并去除首尾空白，以字符串保存并保留前导零；学号是唯一业务标识，创建后不可修改，
  Service 会拒绝任何与数据库现有值不同的学号，编辑界面学号只读。新增与编辑都在事务内做
  最终唯一性校验。
- 成功业务写入与成功审计日志处于同一事务，审计失败则整体回滚；失败操作的审计为独立
  best-effort 尝试，不会覆盖原始业务错误。
- 审计摘要只包含学号、姓名等必要信息，不记录身份证号。
- 查询支持筛选、白名单排序与分页（每页 20/50/100 条），页码越界自动夹紧。

## 证书编号

- 三类编号（毕结业、学位、其他）各自维护独立的四段固定文本、序号位数与流水。
- 编号由非空固定文本按顺序直接拼接、再加左侧补零的流水号组成；固定文本去除首尾空白，
  空片段被忽略，不自动添加分隔符。流水号超过配置位数时完整保留，不截断。
- 预览只读：不写数据库、不递增流水、不占用编号。预览与正式生成共用同一拼接函数。
- 正式生成在单个事务内完成规则读取、流水读取、编号计算、唯一性检查、编号写入、
  流水递增与成功审计；冲突或任一步骤失败都整体回滚，不跳号、不消耗流水、不覆盖已有编号。
- 编号写入遵循现有唯一约束：同一编号字段内唯一，不同证书类型的字段之间允许出现相同文本。
- 规则更新与成功审计处于同一事务；下一流水号在界面中只读，仅正式生成后自动递增。
- 界面入口：`编号管理` 菜单中的“编号规则设置”和“生成证书编号”，学生表格工具栏也有
  “生成编号”按钮（需先选中记录）。

## 学生照片

- 当前只实现毕业照片，支持 JPG/JPEG；数据库 `certificate_records.photo_path` 保存相对于
  `photos/` 的单层文件名（如 `00123.jpg`），不保存绝对路径。
- 首选文件名为 `{学号}.jpg`，冲突时使用 `{学号}_{8位UUID}.jpg` 安全备用名；写入采用独占
  创建，绝不覆盖已有文件。
- 加载照片只依据数据库 `photo_path`，不会按学号推导或关联未登记的文件；文件缺失、损坏或
  路径不安全时界面显示占位提示。
- 更换照片时先校验并复制新文件，再在同一数据库事务中更新 `photo_path` 与成功审计；
  事务提交成功后才清理旧文件。数据库更新或审计失败时回滚并尽力清理新文件，保留旧照片与
  旧关联。
- 清理旧照片前检查路径安全与其他记录引用；被其他记录引用或路径异常的文件不删除。删除
  学生记录不会删除照片文件。
- 图片内容使用 PySide6 `QImageReader` 校验：除文件头外必须实际解码出非空图像，并确认
  JPEG 结束标记存在，损坏或截断文件会在保存前被拒绝；不新增 Pillow 依赖。
- 学生字段更新与照片关联更新保持独立事务。字段已保存而照片保存失败时，界面明确提示
  字段修改已保存、照片尚未更新且取消不会撤销字段修改；重试时不会重复提交未变化字段。

## Excel 导入

- 仅支持固定 37 列的 `.xlsx` 模板，列名与顺序唯一来源是 `app/utils/excel_template.py` 中的
  `EXCEL_COLUMN_NAMES`，与 `schema.py` 的 `EXCEL_FIELD_NAMES` 一一对应。
  这些列名取自提示词包 C.2，**不等同于**界面上的字段标签（如「院号」「层次」「当前年级」）；
  表头按 C.2 列名严格校验，任何缺失、多余、改名或换序都会整批失败。
- 使用 `openpyxl` 只读模式读取；不使用 `photo_path` 列。空行忽略，空单元格按空值处理。
- 学号始终按文本处理并保留前导零；若单元格被 Excel 存成数值或布尔等非文本类型，会明确报错
  并提示将列设为文本，不猜测、不补零。其余文本字段只去除首尾空白，不做类型改写。
- 日期字段接受文本 `YYYY-MM-DD`（必须真实存在）或 Excel 纯日期；带时间部分的日期会被拒绝。
- 导入前读取并校验整个文件：逐行收集学号必填、文件内重复、数据库已有学号、三类证书编号
  非空、类型与日期错误等全部可定位问题，错误报告包含 Excel 行号、C.2 列名与字段名。
  任意错误都整批失败，不会只导入有效行，不会自动清空证书编号，不会覆盖已有记录或照片。
- 全部学生记录、成功批次与成功审计处于同一事务；任一步失败整体回滚。失败时业务事务已回滚，
  再由独立事务 best-effort 保存失败批次与失败审计；失败审计记录文件名、总行数、失败行数和
  错误数，详细字段错误保存在 `import_batches.error_summary`。这些记录写入失败不会掩盖原始
  导入错误，而是通过 `batch_saved=False` 或 `warnings` 如实报告。
- 导入不调用编号服务，不生成证书编号，不修改编号规则或流水。
- 界面入口：学生管理页工具栏「导入 Excel」；结果对话框展示总行数、成功/失败条数与逐条错误明细。

## 证书模板与渲染

- 模板使用可版本化的 JSON（`format_version = 1`），顶层字段与 `certificate_templates`
  的 `name / certificate_type / canvas_width_mm / canvas_height_mm / template_json` 一一对应；
  保存时这四列一律由经过校验的模板模型派生，读取时校验列与 JSON 一致，不一致报 `TemplateDataError`。
- 所有持久化坐标、尺寸使用毫米，字号使用磅；渲染时按 DPI 换算为像素，不把像素坐标写回模板。
- 元素类型只有 `text` 与 `photo`：
  - 文本元素必须且只能提供 `field`（37 个业务字段之一）或 `text`（静态文字）之一，
    不支持表达式、模板语言或任意代码；未知字段、`photo_path`、越界坐标、零/负尺寸、重复 ID
    在加载阶段直接报错。
  - 照片元素只描述位置、尺寸与 `fit`（`cover` / `contain`），照片来自记录的 `photo_path`。
- 文本行为固定且可预期：`wrap="none"` 单行绘制、换行符降级为空格；`wrap="word"` 按元素宽度自动换行；
  两者都裁切到元素矩形，不自动缩小字号、不添加省略号；`align` / `vertical_align` 控制水平与垂直对齐。
- `CertificateRenderer.paint()` 是唯一绘制路径，`render_to_image()` 只是创建离屏画布并调用它，
  后续打印同样复用 `paint()`，避免预览与打印位置不一致。
- 缺失字段、无照片、照片文件不存在或无法解码只返回带元素 ID 的 `RenderWarning`，
  跳过该元素继续渲染，不抛异常、不中断整张证书。
- 内置模板为只读资源（`resources/templates/builtin_*.json`，A4 横版 297×210mm）；
  `TemplateService.seed_builtin_templates()` 必须由调用方传入显式事务连接，
  重复播种只跳过、不覆盖已有内置模板；本阶段尚未接入启动与重置流程。

## 模板设计器

- 入口：主窗口「模板管理 → 模板设计器」。
- 左侧模板列表展示名称、证书类型、画布尺寸与内置/自定义状态；支持新建、复制与删除。
  内置模板可打开和预览，但不能修改或删除；复制内置模板只会生成**未保存草稿**，
  点击「保存」后才写入新记录，原内置模板不受影响。
- 画布按可用空间自动缩放并保持宽高比；缩放只影响屏幕显示，模板始终保存毫米坐标。
  支持鼠标选中、拖动、四角缩放，以及新增文本/照片元素、删除选中元素。
- 属性面板可精确编辑位置、宽度与高度；文本支持静态文字或业务字段二选一
  （字段下拉不含 `photo_path`）、字体、字号、粗体/斜体、水平/垂直对齐、单行/自动换行；
  照片支持 `cover` / `contain`。
- 所有属性修改与保存都会调用阶段 8 的 `template_from_dict()` 整体校验；非法值只在面板
  或状态栏显示错误，不写入模型、不写入数据库，也不会被静默修正。
- 预览调用 `CertificateRenderer`（与后续打印同一 `paint()` 路径），使用明确标记的示例数据，
  日期等字段按原字符串显示；无学生照片时照片元素返回 `missing_photo` 告警并逐条展示。
- 有未保存修改时切换模板或关闭窗口会先确认；取消或关闭不会留下任何新记录。

## 证书打印

- 入口：学生页工具栏「打印证书」打印当前选中记录；主窗口「打印管理」菜单提供
  「打印选中记录 / 打印当前筛选结果 / 打印勾选记录」。
- 表格首列新增勾选列，勾选跨页保留；筛选或排序变化时清空勾选并提示，避免误打印其他集合。
  批量打印前显示记录数量，并按点击瞬间的快照顺序逐张处理。
- 打印使用 `QPrinter` 与 `QPrintDialog`（可设置打印机、纸张、方向、份数），
  每张证书单独建立打印任务；绘制一律复用 `CertificateRenderer.paint()`。
- 坐标系固定为「纸张左上角 + 设备像素」：`setFullPage(True)`，毫米到设备像素只通过
  渲染器的 `dpi=printer.resolution()` 换算一次，不额外缩放或旋转；纸张更大时按布局可绘制
  区域居中平移，纸张更小时按 1:1 打印并提示可能被裁切。
- `QPageLayout.paintRect()` 仅作为**布局可绘制区域**使用；程序无法可靠获取打印机硬件边距，
  界面固定提示「硬边距无法获取，若边缘被裁切请校准」，不会声称已准确检测。
- 打印状态只记录可观测结果：`failed`（有证据的设备/渲染失败）、`unknown`（渲染完成但
  无法确认驱动是否接受）、`accepted`（仅当设备明确返回接受；Qt 不提供，真实打印不会出现）。
  正常真实打印结果为 `unknown`，界面显示「提交状态无法确认」，不声称物理打印成功。
- 设备或会话失效后立即停止继续提交；未开始的记录单独计数，不写 `print_records`，也不伪装为
  已提交或已尝试失败。用户中止时仅统计已开始的任务。
- 每条尝试独立事务写入 `print_records`（编号快照、类型、模板、打印机、结果、失败原因）；
  审计写入失败时保留打印结果并明确提示「审计不完整」。
- 每次任务另写一条 `operation_logs` 批次摘要，沿用现有字段与 `success/failure/unknown` 结果：
  包含批次唯一 ID、模板名称/尺寸、打印机与各状态计数，以及**实际写入成功的**
  `print_records.id` 清单；清单过长会截断、单条审计失败会缺失对应 ID，均会显式告警，
  不声称批次关联完整。
- 数据库没有对应类型模板时回退读取 `resources/templates` 中的只读内置模板，
  此时 `print_records.template_id` 为 `NULL`，模板身份记录在批次摘要中。

## 证书核验

- 入口：学生管理页工具栏「核验证书」；主窗口「核验管理 → 核验证书…」。
- 进入核验时按学生页当前的筛选条件与排序顺序建立会话快照，固定记录 ID 集合与顺序；
  学生页之后修改筛选、排序或勾选，不会自动改变已打开的核验会话。
- 进入时可选择一个证书类型（毕结业 / 学位 / 其他），一个会话只使用一种证书类型；
  切换类型属于显式重建会话，并回到第一条。
- 会话内提供「上一条 / 下一条 / 重新载入 / 关闭」。导航按钮是否可用只取决于集合边界与
  当前位置，不会仅因单条读取失败而禁用。
- 「重新载入」按本会话保存的筛选与排序重新查询并回到第一条，不读取学生页的当前状态。
- 每条记录都实时读取数据库当前值，不冻结字段内容；界面展示学号、姓名、学院、专业、班级、
  所选证书类型的证书编号与核验状态，不展示身份证号码。
- 状态只有四种：「可核对」「缺少证书编号」「记录已删除」「读取失败」。
  「可核对」仅表示记录存在且所选类型的证书编号非空，**不代表**证书真实、有效，也不代表
  已与任何外部数据完成核验。
- 集合中的记录被删除后保留其位置并显示「记录已删除」，可继续上一条/下一条；
  数据库读取异常显示普通用户可理解的重试提示，详细异常只写入运行日志。
- 核验全程只读：不修改学生信息、证书编号、照片、模板或打印记录，不写入 `operation_logs`、
  `print_records` 与 `number_sequences`，也不保存任何核验结论。
- 尚未实现：照片展示、核验结果保存、外部权威系统匹配、输入证书编号反查、批量统计与结果导出。

## 已实现范围

阶段 1：项目骨架、统一路径管理、日志初始化、主窗口空壳。

阶段 2：SQLite 连接与事务管理、Schema（9 张表、约束、索引、外键）、版本管理、
幂等初始化与默认数据播种、启动接入与测试。

阶段 3：8 张业务表的 Repository 数据访问层与专项测试。

阶段 4：学生数据管理基础——StudentService、数据表格界面、筛选/排序/分页、
单条新增/编辑/删除、学号校验与审计日志。
